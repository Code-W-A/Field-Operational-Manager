# Revizii automate în dashboard

Reviziile automate nu mai intră în containerul **Listate**. Reviziile create manual păstrează criteriile existente. În **Programator revizii**, tichetele sunt asociate după contract, zi și locație; o revizie manuală nu poate înlocui o revizie automată în aceeași zi.

Identificare: `tipLucrare = Revizie` și `autoGenerated === true`. Numai dacă indicatorul lipsește (`null`/`undefined`), se acceptă proveniența veche `createdBy = system` + `createdByName = CRON Revizie`. Un `false` explicit rămâne manual. Contractul sau programarea singure nu înseamnă generare automată.

ID-ul locației are prioritate. Numele este fallback pentru înregistrări vechi fără ID; numele identice nu suprascriu ID-uri diferite și asocierile ambigue nu produc linkuri arbitrare. Limitele și intervalul de afișare existente ale Programatorului rămân neschimbate.

Atribuirea se face în tichetul deschis din Programator. După atribuire dispare din acel container și apare la tehnician. Sursa comună a listelor și contoarelor este `useDashboardStatus`, utilizată atât de containerele desktop, cât și de dialogurile mobile.

## Verificări locale

```sh
./node_modules/.bin/tsx --test lib/utils/dashboard-revisions.test.ts
node --test hooks/use-dashboard-status.revisions.test.mjs
npm run test:equipment-status
npm run build
```

8 teste de clasificare/asociere, 3 teste cu hookul real și colecții în memorie, plus 33 de regresii Stare echipament. Testele hookului verifică inclusiv trecerea unei singure locații la tehnician după atribuire. Nu scriu în Firebase și nu testează persistența atribuirii în producție.

Schimbarea nu modifică generatorul, statusurile salvate, documentele existente, API-urile, Expo sau celelalte containere. Nu necesită migrare ori deploy Firebase Functions. Publicarea aplicației web și verificarea în producție sunt separate; nu au fost efectuate în această intervenție.

Buildul Next.js a trecut, dar configurația existentă omite verificarea TypeScript/lint în build. Verificarea separată `tsc --noEmit --incremental false` raportează erori preexistente în proiect (inclusiv câmpuri lipsă în configurația implicită DashboardStatusConfig); nu raportează erori în noul helper sau în testele sale. Nu se revendică un typecheck global verde.
